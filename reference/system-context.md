# Cowork — system context

บริบทเพื่อให้ AI "วางแผนงานได้สมเหตุสมผล" ไม่ใช่แค่กรอกช่องให้ถูก
(อ้างอิงจากพฤติกรรมจริงของแอป — ถ้าไม่แน่ใจเรื่องข้อมูลของโปรเจกต์ใดโปรเจกต์หนึ่ง ให้ถามผู้ใช้)

## โครงสร้าง

```
Client (อนาคต) → Project → Stage (ช่วงงาน) → Task (งาน) → Checklist (ติ๊กย่อยในงาน)
```

- **Project** = โปรเจกต์หนึ่งงานของทีม มีเจ้าของ (owner), งบ, ช่วงวันของ pitch และของ work
- **Stage** = "ช่วงงาน" ที่ใช้จัดกลุ่ม task เช่น Research / Design / Production · แต่ละ stage สังกัด **เฟลเดียว** (pitch หรือ work)
- **Task** = งานย่อย มีสถานะ/ความสำคัญ/ผู้รับผิดชอบ/ช่วงเวลา/ชั่วโมง
- **Checklist** = รายการติ๊กย่อยในแต่ละ task (import ทาง .xlsx ยังไม่แตะ checklist)

## 2 เฟสของโปรเจกต์: pitch vs work

- **pitch** = ช่วงเสนองาน/ประมูล (proposal, pitching) — งานวิจัย ร่างไอเดีย ทำสไลด์ ยังไม่ใช่งานผลิตจริง
- **work** = ช่วงผลิตจริงหลังได้งาน
- โปรเจกต์มีช่วงวันแยกกันสองชุด (pitch start/end กับ work start/end) และ Stage/คน ก็ผูกกับเฟส
- เวลาวางแผน: งานช่วงเสนอ → `Phase = pitch`, งานผลิต → `Phase = work`

## บทบาทในทีม (positions)

- **PM** — project manager, ดูภาพรวม/มอบหมาย
- **Lead** — หัวหน้าสายงาน
- **Designer** — ทำงานดีไซน์

> สิทธิ์แก้ข้อมูลโปรเจกต์เป็นของ PM / Lead / admin — แต่การ **import ต้องกดโดยคนที่มีสิทธิ์จัดการโปรเจกต์**อยู่แล้ว
> AI แค่เตรียมไฟล์ ผู้ใช้ที่มีสิทธิ์เป็นคนอัปโหลด+อนุมัติ

## Assignees

- มอบหมายด้วย **อีเมล** และอีเมลนั้นต้องเป็น **สมาชิกของโปรเจกต์** (อยู่ในชีต Team ของไฟล์ Export)
- ใส่หลายคนได้ คั่นด้วยจุลภาค · จะไม่มอบหมายก็เว้นว่าง
- อย่าเดาอีเมล — ถ้าไม่รู้ ให้เว้นว่างหรือถามผู้ใช้ (อีเมลผิดจะถูกตีกลับ)

## การประเมินเวลา (Estimate) — วางแผนให้พอเชื่อถือได้

- `Estimate (hrs)` = ชั่วโมงที่คาดว่าจะใช้ · `Actual (hrs)` = ชั่วโมงจริง (กรอกทีหลัง ปกติเว้นว่างตอนวางแผน)
- เวลาเสนอแผน ให้ประเมินเป็นชั่วโมงตามจริงของงานดีไซน์/โปรดักชัน อย่าใส่ตัวเลขมั่ว
- กระจายวัน Start/Due อย่าให้ทับกันจนคนคนเดียวทำหลายงานพร้อมกันเกินจริง (Cowork มีมุมมองภาระงานรายคน ถ้าอัดงานชนกันจะขึ้นเป็น over-allocation)

## สถานะงาน

- `todo` → `in_progress` → `done`
- แผนใหม่ที่ยังไม่เริ่ม ให้ตั้ง `todo`

## หลักคิดเวลาช่วยวางแผน

1. เรียงงานตามลำดับที่ทำจริง (research ก่อน design ก่อน production)
2. จัดกลุ่มด้วย Stage ให้ตรงเฟส — ช่วยให้ timeline ในแอปอ่านง่าย
3. อย่าสร้างสิ่งที่ import สร้างไม่ได้ (Stage ใหม่, สมาชิกใหม่) — ถ้าจำเป็นให้บอกผู้ใช้ไปสร้างในแอปก่อน
4. เสนอเป็น "ร่าง" เสมอ — คนจะเห็นทุกแถวในหน้า preview แล้วปรับ/อนุมัติเอง
