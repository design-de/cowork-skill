# Tasks sheet — import contract

> **ไฟล์นี้ถูก generate อัตโนมัติ** จาก `cowork-app/lib/taskImportContract.js` — อย่าแก้ด้วยมือ
> แก้สัญญาในแอปแล้วรัน `node scripts/gen-skill-contract.mjs` เพื่ออัปเดตไฟล์นี้ให้ตรงกัน
> Format version: 1
>
> (ไม่ประทับวันที่ไว้ตรงนี้ตั้งใจ — จะได้รัน generator ซ้ำเพื่อ "เช็ค drift" ได้ โดยไฟล์ไม่เปลี่ยนถ้าสัญญาไม่เปลี่ยน)

ตอน import แอปอ่านชีตชื่อ **`Tasks`** เท่านั้น
จับคอลัมน์จากข้อความหัวตาราง — ห้ามแก้หัว · แถวหัวตาราง = แถวที่คอลัมน์ A เขียนว่า "Title" (ในไฟล์ Export จริงอยู่แถวที่ 4)

## คอลัมน์ (A–L)

| Col | Header (ตรงเป๊ะ) | Type | Required | กติกา |
|---|---|---|---|---|
| A | `Title` | text | yes | ชื่องาน จำเป็นทุกแถว |
| B | `Status` | enum | no | todo \| in_progress \| done (ตัวเล็ก) · ว่าง: แถวใหม่=todo, แถวเดิม=คงค่าเดิม |
| C | `Priority` | enum | no | low \| med \| high · ว่าง: แถวใหม่=med, แถวเดิม=คงค่าเดิม |
| D | `Phase` | enum | no | pitch \| work — pitch = ช่วงเสนอ/ประมูล · work = ช่วงผลิตจริง · ว่าง: แถวใหม่=work, แถวเดิม=คงค่าเดิม |
| E | `Stage` | text | no | ชื่อ "ช่วงงาน" ที่จัดกลุ่ม task (เช่น Research, Design) · ตรงกับ Stage ที่มีอยู่แล้วในโปรเจกต์ เฟสเดียวกัน (ดูรายชื่อ STAGES) · ชื่อใหม่ที่ยังไม่มี = ระบบสร้างช่วงให้อัตโนมัติ (โชว์ในหน้า preview ก่อน) · ใช้ชื่อเดิมเป๊ะเพื่อให้งานอยู่ช่วงเดียวกัน · ว่าง = ไม่มีช่วง (งานทั่วไป) · แถวเดิมที่เว้นว่าง = ถอดออกจากช่วง |
| F | `Assignees (email)` | text | no | อีเมลคั่นด้วยจุลภาค ทุกอีเมลต้องมีในชีต Team (เป็นสมาชิกโปรเจกต์) · ว่าง = ไม่มอบหมาย |
| G | `Start` | date | no | YYYY-MM-DD (เป็น cell วันที่จริงหรือ text ก็ได้) |
| H | `Due` | date | no | YYYY-MM-DD · ถ้าใส่แค่ Start หรือ Due อย่างเดียว = งานวันเดียว |
| I | `Estimate (hrs)` | number | no | ชั่วโมงที่ประเมิน (จำนวนบวก) |
| J | `Actual (hrs)` | number | no | ชั่วโมงจริง (ปกติกรอกหลังทำเสร็จ) |
| K | `Description` | text | no | ข้อความอิสระ ช่องเดียว |
| L | `ID (ห้ามแก้)` | uuid | system | ห้ามแก้/ห้ามแต่ง ID · แถวมี ID = แก้งานนั้น · ID ว่าง = สร้างงานใหม่ |

คอลัมน์ **หลังคอลัมน์สุดท้าย** ในไฟล์ Export คือ timeline (แถบสี Gantt) ที่ระบบวาดเอง — **ห้ามเขียน** import มองข้าม

## บริบท

- ไฟล์นี้คือ export ของโปรเจกต์เดียวจาก Cowork — ชีตเดียวที่ import กลับได้คือ "Tasks"
- Project / Team / Milestones / Allocation เป็นข้อมูลอ้างอิงดูอย่างเดียว แก้ไปก็ไม่มีผลตอน import
- import แค่แก้งานเดิมกับสร้างงานใหม่ ไม่เคยลบอะไร · คนตรวจทุกการเปลี่ยนในหน้า preview ก่อนบันทึก
- วิธี import: เปิดโปรเจกต์ใน Cowork กดปุ่ม "Import" (เฉพาะผู้จัดการโปรเจกต์) แล้วอัปโหลดไฟล์

## กติกา

1. แก้งาน: เปลี่ยนค่าในแถวของมัน โดยคง ID เดิม
2. เพิ่มงาน: เพิ่มแถวใหม่ เว้น ID ว่าง (เพิ่มได้ไม่จำกัด — dropdown ที่ preset ~50 แถวเป็นแค่ความสวย เกินนั้นก็ import ได้)
3. ห้ามลบแถวเพื่อลบงาน — import ไม่ลบ แถวที่หายไปแค่ถูกปล่อยไว้เฉยๆ
4. คอลัมน์ M เป็นต้นไปคือ timeline ที่ระบบวาดเอง (ระบายสีจาก Start/Due) ห้ามเขียน — import มองข้าม
5. วันที่ต้อง YYYY-MM-DD ห้าม 13/7/2026 หรือ "Jul 13"
6. ห้ามแก้ชื่อชีต "Tasks", ข้อความหัวคอลัมน์, และบล็อก FILE METADATA — แม้จะ generate ไฟล์ใหม่ด้วยโปรแกรม
7. แถวที่อีเมลไม่รู้จัก / enum พิมพ์ผิด / วันที่ผิดรูป จะถูกตีกลับพร้อมเหตุผลในหน้า preview — แถวอื่นยัง import ได้

## Stage (ช่วงงาน)

ใช้ชื่อเหล่านี้ให้ตรง (ไม่สนตัวพิมพ์เล็ก/ใหญ่) เพื่อวางงานในช่วงที่มีอยู่ · ชื่ออื่นที่ไม่มีในรายการ = สร้างช่วงใหม่ในเฟสของงานนั้นให้อัตโนมัติ — หน้า preview จะลิสต์ช่วงใหม่ทุกช่วงให้ดูก่อนอนุมัติ
ไฟล์ Export จริงจะแนบ "รายชื่อ Stage ที่ใช้ได้" แยกตามเฟส (pitch/work) มาในชีต AI Guide

## FILE METADATA (บล็อกในชีต AI Guide — ห้ามแก้)

```
PROJECT_ID: <uuid ของโปรเจกต์>
EXPORTED_AT: <ISO timestamp>
FORMAT_VERSION: 1
```

- `PROJECT_ID` บอกว่าไฟล์เป็นของโปรเจกต์ไหน — ควรคงไว้ให้ตรงกับโปรเจกต์ที่จะ import เข้า
- `EXPORTED_AT` ใช้ติดธง ⚠ ถ้ามีคนแก้งานในแอป "หลัง" ไฟล์ถูก export — อย่าปลอมเป็นเวลาปัจจุบัน
- ไฟล์ที่สร้างใหม่จากศูนย์ (ไม่มี metadata) จะถูกมองว่าทุกแถวเป็นงานใหม่ในโปรเจกต์ที่กำลัง import อยู่

## เคล็ดลับ — เสนอแผนทั้งชุด

เติมแถวใหม่เยอะๆ (Title, Phase, Start, Due, Estimate, Assignees; Status = todo) แล้วคนอนุมัติทั้งหมดในหน้า preview ของแอป
